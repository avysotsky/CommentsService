# CommentsService

Версия: **1.1.0.9** · Ветка: `CommentsService/v_1.1.0.9_Captcha`

[English](README.md) · [Русский](README.RU.md) · [Українська](README.UA.md)

[История изменений](change.log.ru) · [Краткая инструкция](read.me) · [План](docs/PLAN.md)

React и .NET 10 работают в одном Docker-контейнере с постоянной PostgreSQL 17.
Выпуск создаёт и читает текстовые комментарии через API, проверяет ввод и сохраняет
метаданные клиента на сервере. Onion отделяет Domain/Application от EF и HTTP.
SPA содержит форму, таблицу последних комментариев, клиентскую валидацию, отправку
без перезагрузки, сохранение черновика при ошибке и переключение EN/RU/UA.
Вложения относятся к последующим этапам.

Обновление 1.1.0.8 → 1.1.0.9 меняет только приложение: сохраните схему/данные/копии/тома, соберите и перезапустите приложение, проверьте обе БД. Прежние миграции идемпотентны.

[Контракт API и примеры](docs/API.md) · [Архитектура](docs/ARCHITECTURE.md)

## Развёртывание на своей инфраструктуре

Нужны Docker Engine, Compose v2.24+, Git и Python 3. Docker собирает .NET/React;
SDK и Node на хосте для развёртывания не нужны. Из корня репозитория:

```bash
python3 scripts/init-env.py
docker compose -p commentsservice --profile testing up -d --wait database test-database
python3 scripts/db-checkpoint.py
docker compose -p commentsservice build app
python3 scripts/db-command.py migrate
python3 scripts/db-command.py migrate --service test-database
docker compose -p commentsservice up -d --no-build --wait
curl --fail http://127.0.0.1:8080/health/database
```

Откройте http://localhost:8080 на Docker-хосте. При необходимости используйте sudo.
`commentsservice` — пример имени проекта; сохраняйте его и файл окружения при
обновлениях, чтобы использовать прежние тома. Другой порт можно выбрать один раз:
`python3 scripts/init-env.py --port 8081`.

Тестовая БД — отдельный постоянный сервис профиля `testing`.
Проверка контрольной копии охватывает обе БД, поэтому сначала запустите обе.
Миграции запускаются явно; приложение не применяет их автоматически при старте.
Перед обновлением схемы/данных остановите запись и проверьте контрольную копию.
Переход 1.1.0.6 → 1.1.0.7 добавил миграцию `20261030101720_CommentThreads`.
Остановите приложение (`docker compose -p commentsservice stop app`), проверьте текущую
контрольную копию, соберите выпуск, явно примените миграции обеих БД и запустите прежние тома.
Старые комментарии сохраняют все поля и становятся корнями (`parentId=null`, `rootId=id`).
Обратная миграция запрещена при наличии ответов; при необходимости восстанавливайте
проверенную копию до обновления, учитывая потерю изменений после контрольной точки.

## Данные и восстановление

- Разработка: БД `comments`, том `commentsservice_development_data`.
- Тесты: `comments_test`, том `commentsservice_test_data`, локальный порт 55434.
- Роль приложения: `comments_app`, без прав суперпользователя, создания ролей и БД.
- Таблицы: `comments.Authors`, `comments.Comments`; история: `comments.__EFMigrationsHistory`.
- Миграции: `20261029195935_InitialDataModel`, `20261030101720_CommentThreads` (добавление полей).
- Контрольные копии: `artifacts/checkpoints`, один проверенный дамп/описание на каждую БД.
  Скрипт восстанавливает их во временные БД с уникальными именами, сравнивает отпечатки
  строк и удаляет только эти временные БД. Прежние копии заменяются после проверки новых.

Храните копии приватно; важные данные дополнительно копируйте в защищённое хранилище.
При создании копии остановите запись; обнаруженные изменения приводят к ошибке проверки.
Обычный запуск и тесты сохраняют БД и тома. Не используйте `down -v` и общую очистку таблиц.
Подробности: [схема и диаграммы](docs/database/SCHEMA.md), [миграции и восстановление](docs/database/MIGRATIONS.md).

## Проверка

```bash
python3 scripts/db-command.py check
python3 scripts/db-command.py check --service test-database
python3 scripts/test-backend.py
```

Для четырёх наборов тестов нужен SDK .NET 10 на хосте. Тесты читают созданный файл
паролей и используют `comments_test`. Тесты БД откатывают транзакции; HTTP-тесты удаляют
только собственные комментарии и оставшиеся без ссылок записи авторов.
Для другой машины/порта укажите `--host`/`--port` в команде тестов.
Скрипты команд БД и контрольных копий принимают `--env-file`, `--project` и повторяемый
`--compose-file`. Используйте одинаковые параметры во всех командах развёртывания.
Чтение паролей рассчитано на формат KEY=value, создаваемый `init-env.py`.

`GET /api/status` возвращает `{"application":"CommentsService","version":"1.1.0.9","stage":"Captcha"}`.
`GET /health` проверяет процесс API; `/health/database` — подключение и неприменённые
миграции, возвращая 503 при недоступности или устаревшей схеме. Неизвестные API-маршруты возвращают 404; маршруты комментариев описаны в docs/API.md.

## Пароли, остановка и IDE

`init-env.py` создаёт приватный `.env` один раз и сохраняет существующий файл.
Не публикуйте пароли и копии БД. Изменение .env не меняет пароль существующей роли.
Приложение слушает loopback; для внешнего доступа настройте свой HTTPS reverse proxy.
Остановка с сохранением данных:

```bash
docker compose -p commentsservice --profile testing down
```

В Visual Studio 2026 откройте `CommentsService.slnx`; нужны SDK .NET 10 и нагрузка
ASP.NET/веб. Решение собирает API и тесты; Frontend содержит редактируемые файлы React.
Docker собирает приложение целиком. Промежуточные каталоги Windows и Linux разделены.
Без переменных БД API/страница статуса запускаются; проверка БД возвращает 503.
Для подключения из IDE задайте `PGHOST`, `PGPORT`, `PGDATABASE`, `PGUSER`, `PGPASSWORD`
в приватном окружении запуска. Не коммитьте их значения.

## Архитектура Onion

Backend содержит четыре проекта: Domain, Application, Infrastructure и Api.
Application содержит сценарии создания/чтения, валидацию и DTO; EF-адаптеры реализуют его контракты хранения.
Infrastructure/Persistence содержит Configurations, Repositories и Migrations.
HTTP endpoints используют контракты приложения/платформы; Infrastructure подключается в Program.cs.
См. [архитектуру и правила зависимостей](docs/ARCHITECTURE.md). Выпуск сохраняет
первую миграцию и существующие данные; схема расширяется миграцией ответов. Далее — 1.1.0.10 ImageAttachments.

## Проверка frontend

С Node.js 24 выполните `npm ci`, `npm test`, `npm run build` в `src/comments-web`.
Форма отправляет обычный текст или разрешённый XHTML; обязательные поля отмечены. Email публикуется.
Таблица показывает 25 корней на странице с местным временем. «Обновить» повторяет чтение.
Ошибки полей сервера выводятся в исходном виде; интерфейс поддерживает EN/RU/UA.
При ошибке отправки черновик остаётся в форме; перед повтором неопределённого запроса
обновите список во избежание дублей. CAPTCHA реализована; далее вложения.

## XHTML-редактор

Разрешены `a`, `i`, `strong`, `code`. Для ссылки обязателен абсолютный HTTP(S) `href` без учётных данных; `title` необязателен. Остальные атрибуты, пространства имён, вложенные ссылки, комментарии, DTD/CDATA, неправильная вложенность и опасные адреса запрещены. XHTML требует закрытых строчных тегов и XML-сущностей (`&amp;`, `&lt;`, `&quot;`); обычный текст `1 < 2 && 3 > 1` также допустим. Лимиты: 65 536 единиц UTF-16, глубина 32 и 4096 узлов парсера.

Выделите текст и нажмите «Жирный», «Курсив», «Код» или «Ссылка». Ссылка вставляет редактируемый HTTPS-шаблон. «Предпросмотр» отправляет `POST /api/comments/preview` с `{ "text": "<strong>Hello</strong>" }` и получает `{ "html": "<strong>Hello</strong>" }` без обращения к БД и записи. Сохранение использует тот же валидатор Application. Правка скрывает устаревший просмотр; ошибка сохраняет черновик. Просмотр и таблица создают только разрешённые React-элементы, безопасные ссылки и экранированный текст при отказе. Существующие записи сохранены; схема расширяется миграцией ответов.

Подсказка необязательного поля сайта требует полный адрес, например `https://example.com`; `http://` также поддерживается. Форма не выбирает протокол и не проверяет доступность сайта.

## Ветки комментариев

Ответить можно на любой существующий комментарий. Нажмите «Ответить» под записью; форма покажет адресата. «Отменить ответ» возвращает создание корня и сохраняет черновик. Успешный ответ появляется под родителем; отсутствующий адресат вызывает ошибку без создания автора или комментария.

Таблица показывает 25 корней на странице в выбранном порядке. «Показать/Скрыть ответы» раскрывает прямые ответы; «Ещё ответы» загружает следующие 25. Ответы идут по времени UTC/UUID по убыванию, корни — в выбранном порядке. Глубина обсуждения не ограничена приложением: вывод итеративный, визуальный отступ перестаёт расти после шести уровней, числовой уровень продолжает расти. «Обновить» перечитывает корни и открытые ветки; ошибка ветки предлагает «Повторить» и сохраняет загруженное содержимое. Полные страницы/сортировки корней реализованы в этой версии.

API: POST /api/comments принимает необязательный parentId (UUID/null); rootId определяет сервер, передавать его нельзя. GET /api/comments/{id}/replies?limit=25&after={replyId} возвращает {items,nextAfter}; для первой порции after не указывается. Limit — 1–100; after должен быть прямым ответом этому родителю. Нет родителя: 404 при чтении, ошибка parentId (400) при записи. Неизвестный/чужой курсор — 400. Порции ограничивают соседние ответы, а не глубину. API удаления/редактирования не добавлен.

## Сортировка и страницы корней

SPA загружает `GET /api/comments/page?page=1&sort=createdAt&direction=desc`. Поля сортировки: `userName`, `email`, `createdAt`; порядок: `asc` или `desc`. По умолчанию дата убывает — LIFO. На странице **25 корней**, без учёта ответов. Ответ API: `items`, `page`, `pageSize`, `totalCount` (только корни), `totalPages`. Page — целое 1–85 899 345; неверные поля/порядок дают 400. После последней страницы API возвращает пустой items с реальными итогами; SPA исправляет устаревший адрес на последнюю страницу либо первую для пустого списка. Для пустого списка totalPages=0.

Доступны все шесть сочетаний сортировки; изменение возвращает на первую страницу. Первая/Предыдущая/Следующая/Последняя и переход по номеру управляют страницами; адрес сохраняет page/sort/direction при перезагрузке. Черновик не пропадает. Новый корень возвращает на первую страницу новых записей; ответ сохраняет текущую страницу и не меняет число корней. У ответов прежние кнопки раскрытия/скрытия/дозагрузки. Ошибка обновления сохраняет прежние результаты; повтор — «Обновить».

Равные значения упорядочены по UUID в том же направлении. Имя/email используют сопоставление БД, дата — UTC. Количество и строки читаются в одном repeatable-read снимке запроса. Разные запросы страниц отражают текущие данные: параллельное добавление может сдвигать offset-границы. Совместимый `GET /api/comments?limit=25` сохраняет массив последних корней. В 1.1.0.8 новой миграции схемы нет.

## CAPTCHA

Каждый комментарий/ответ требует новой проверки. `GET /api/captcha` возвращает `{id,imageDataUrl,expiresAt}` с растровой PNG-картинкой и заголовками no-store; ответ текстом или метаданными не выдаётся. Введите шесть латинских букв/цифр с картинки, регистр не важен. Код действует **5 минут**. `GET /api/captcha?replace={oldId}` отменяет прежнюю проверку и выдаёт новую.

POST /api/comments дополнительно требует `captchaId` (UUID) и `captchaCode`. Вызов проверки расходует ID, в том числе при неверном ответе; отсутствие, просрочка, замена или повтор дают 400 с `errors.captchaCode`, без подготовки автора/комментария. Остальные поля проверяются до CAPTCHA; после успешной проверки ошибка родителя/хранилища тоже расходует код. После неудачной или неопределённой отправки обновите картинку перед повтором. Предпросмотр и чтение CAPTCHA не требуют.

Форма загружает/обновляет картинку, блокирует отправку при загрузке/просрочке/недоступности и сохраняет черновик при ошибке. После любой попытки POST получает новую проверку. Подписи/ошибки — EN/RU/UA. Хранилище в памяти процесса ограничено 2 048 проверками, освобождает просроченные записи и возвращает 429 при заполнении. Перезапуск/пересоздание приложения отменяет оставшиеся коды. Разные экземпляры имеют раздельные коды; для этой версии используйте один экземпляр. PNG создаётся переносимыми средствами .NET без платформенной графики. В памяти остаются только хеш ответа и срок; данные CAPTCHA и миграция в PostgreSQL не добавляются.
