[История изменений](change.log.ru) · [Краткая инструкция](read.me) · [План](docs/PLAN.md)

В этой версии frontend React и API .NET работают вместе в одном Docker-контейнере.
Отдельная PostgreSQL использует постоянное хранилище. Необязательный отдельный
сервис PostgreSQL предоставляет постоянную БД интеграционных тестов.

Комментарии, сущности Entity Framework и работа приложения с БД пока не реализованы;
следующая итерация — DataModel. Английская стартовая страница показывает связь
с API и выпуск. Это этап разработки, а не завершённый сервис комментариев.

## Развёртывание на своей инфраструктуре

Нужны Docker Engine, Docker Compose v2.24+, Git и Python 3 для генерации паролей.
Docker собирает .NET и React; устанавливать .NET/Node на сервер отдельно не нужно.
Из корня клонированного репозитория:

```bash
python3 scripts/init-env.py
docker compose -p commentsservice up -d --build --wait
curl --fail http://127.0.0.1:8080/health
```

Откройте http://localhost:8080 на машине с Docker. Если установка требует,
выполняйте Docker-команды через sudo. Первый запуск инициализирует пустой том БД;
последующие сохраняют его. `--wait` дожидается проверок готовности контейнеров.

`commentsservice` — пример имени проекта. Можно выбрать своё, но при обновлениях
его нужно сохранять, чтобы использовать прежние тома данных. При генерации
окружения можно выбрать другой свободный порт приложения, например
`python3 scripts/init-env.py --port 8081`.

## Постоянные базы данных

- `database`: база `comments`, том `commentsservice_development_data`.
- `test-database`: база `comments_test`, том `commentsservice_test_data`;
  включается необязательным профилем `testing`.
- У каждого сервиса отдельный пароль и прикладная роль `comments_app` без SUPERUSER.
- Прикладных таблиц и миграций EF в этой итерации ещё нет.

Чтобы запустить и постоянную тестовую БД:

```bash
docker compose -p commentsservice --profile testing up -d --wait test-database
```

Тестовая БД доступна только через 127.0.0.1:55434. Другой порт задаётся параметром
`--test-db-port` при генерации паролей. Порт основной БД наружу не публикуется.
Тесты сохраняют БД, откатывают изменения либо удаляют только свои записи.
Пересоздание БД и TRUNCATE общих таблиц не используются для обычных тестов.

Остановка контейнеров с сохранением данных:

```bash
docker compose -p commentsservice --profile testing down
```

Не используйте `down -v`, если данные нужно сохранить. При обновлении выберите
ветку нужного выпуска и повторите запуск с прежним именем проекта и файлом окружения.
Перед будущими изменениями схемы/данных сохраняйте проверенную предыдущую контрольную копию.

## Пароли и доступ

Инициализатор один раз создаёт приватный .env со случайными паролями и не
перезаписывает существующий файл. Не коммитьте и не передавайте этот файл.
Если существующий файл неполон, создайте отдельный через `--output` и передайте
Compose параметр `--env-file`. Изменение .env не меняет пароли существующих ролей PostgreSQL.

Порт приложения привязан к 127.0.0.1. Для внешнего доступа подключите свой HTTPS
reverse proxy; эта версия не создаёт домен и публичный хостинг.

## Проверка состояния

`GET /api/status` возвращает:

```json
{"application":"CommentsService","version":"1.1.0.2","stage":"Docker"}
```

`GET /health` проверяет готовность процесса API. Готовность PostgreSQL проверяется
Compose отдельно; приложение пока не подключается к базам. Контейнер приложения
работает от непривилегированного пользователя. В Dockerfile и скриптах нет встроенных
паролей или инструкций конкретного рабочего компьютера.
