# CommentsService

Версія: **1.1.0.7** · Гілка: `CommentsService/v_1.1.0.7_CommentThreads`

[English](README.md) · [Русский](README.RU.md) · [Українська](README.UA.md)

[Історія змін](change.log.ua) · [Коротка інструкція](read.me) · [План](docs/PLAN.md)

React і .NET 10 працюють в одному Docker-контейнері з постійною PostgreSQL 17.
Випуск створює та читає текстові коментарі через API, перевіряє ввід і зберігає
метадані клієнта на сервері. Onion відокремлює Domain/Application від EF і HTTP.
SPA містить форму, таблицю останніх коментарів, клієнтську валідацію, надсилання
без перезавантаження, збереження чернетки за помилки та перемикання EN/RU/UA.
CAPTCHA і вкладення належать до подальших етапів.

[Контракт API та приклади](docs/API.md) · [Архітектура](docs/ARCHITECTURE.md)

## Розгортання на власній інфраструктурі

Потрібні Docker Engine, Compose v2.24+, Git і Python 3. Docker збирає .NET/React;
SDK і Node на хості для розгортання не потрібні. Із кореня репозиторію:

```bash
python3 scripts/init-env.py
docker compose -p commentsservice --profile testing up -d --wait database test-database
python3 scripts/db-checkpoint.py
docker compose -p commentsservice build app
python3 scripts/db-command.py migrate
python3 scripts/db-command.py migrate --service test-database
docker compose -p commentsservice up -d --no-build --wait
curl --fail http://127.0.0.1:8080/health/database
```

Відкрийте http://localhost:8080 на Docker-хості. За потреби використовуйте sudo.
`commentsservice` — приклад назви проєкту; зберігайте її та файл оточення під час
оновлень, щоб використовувати попередні томи. Інший порт можна вибрати один раз:
`python3 scripts/init-env.py --port 8081`.

Тестова БД — окремий постійний сервіс профілю `testing`.
Перевірка контрольної копії охоплює обидві БД, тому спочатку запустіть обидві.
Міграції запускаються явно; застосунок не застосовує їх автоматично під час старту.
Перед оновленням схеми/даних зупиніть запис і перевірте контрольну копію.
Перехід 1.1.0.6 → 1.1.0.7 додає міграцію `20261030101720_CommentThreads`.
Зупиніть застосунок (`docker compose -p commentsservice stop app`), перевірте поточну
контрольну копію, зберіть випуск, явно застосуйте міграції обох БД та запустіть попередні томи.
Старі коментарі зберігають усі поля й стають коренями (`parentId=null`, `rootId=id`).
Зворотну міграцію заборонено за наявності відповідей; за потреби відновлюйте
перевірену копію до оновлення, враховуючи втрату змін після контрольної точки.

## Дані та відновлення

- Розробка: БД `comments`, том `commentsservice_development_data`.
- Тести: `comments_test`, том `commentsservice_test_data`, локальний порт 55434.
- Роль застосунку: `comments_app`, без прав суперкористувача, створення ролей і БД.
- Таблиці: `comments.Authors`, `comments.Comments`; історія: `comments.__EFMigrationsHistory`.
- Міграції: `20261029195935_InitialDataModel`, `20261030101720_CommentThreads` (додавання полів).
- Контрольні копії: `artifacts/checkpoints`, один перевірений дамп/опис для кожної БД.
  Скрипт відновлює їх у тимчасові БД з унікальними назвами, порівнює відбитки
  рядків і видаляє лише ці тимчасові БД. Попередні копії замінюються після перевірки нових.

Зберігайте копії приватно; важливі дані додатково копіюйте в захищене сховище.
Під час створення копії зупиніть запис; виявлені зміни спричиняють помилку перевірки.
Звичайний запуск і тести зберігають БД та томи. Не використовуйте `down -v` і загальне очищення таблиць.
Докладніше: [схема й діаграми](docs/database/SCHEMA.md), [міграції та відновлення](docs/database/MIGRATIONS.md).

## Перевірка

```bash
python3 scripts/db-command.py check
python3 scripts/db-command.py check --service test-database
python3 scripts/test-backend.py
```

Для чотирьох наборів тестів потрібен SDK .NET 10 на хості. Тести читають створений файл
паролів і використовують `comments_test`. Тести БД відкочують транзакції; HTTP-тести видаляють
лише власні коментарі й записи авторів, що залишилися без посилань.
Для іншої машини/порту вкажіть `--host`/`--port` у команді тестів.
Скрипти команд БД і контрольних копій приймають `--env-file`, `--project` та повторюваний
`--compose-file`. Використовуйте однакові параметри в усіх командах розгортання.
Читання паролів розраховано на формат KEY=value, створюваний `init-env.py`.

`GET /api/status` повертає `{"application":"CommentsService","version":"1.1.0.7","stage":"CommentThreads"}`.
`GET /health` перевіряє процес API; `/health/database` — підключення та незастосовані
міграції, повертаючи 503 за недоступності або застарілої схеми. Невідомі API-маршрути повертають 404; маршрути коментарів описані в docs/API.md.

## Паролі, зупинка та IDE

`init-env.py` створює приватний `.env` один раз і зберігає наявний файл.
Не публікуйте паролі та копії БД. Зміна .env не змінює пароль наявної ролі.
Застосунок слухає loopback; для зовнішнього доступу налаштуйте власний HTTPS reverse proxy.
Зупинка зі збереженням даних:

```bash
docker compose -p commentsservice --profile testing down
```

У Visual Studio 2026 відкрийте `CommentsService.slnx`; потрібні SDK .NET 10 і навантаження
ASP.NET/веб. Рішення збирає API й тести; Frontend містить редаговані файли React.
Docker збирає весь застосунок. Проміжні каталоги Windows і Linux розділено.
Без змінних БД API/сторінка статусу запускаються; перевірка БД повертає 503.
Для підключення з IDE задайте `PGHOST`, `PGPORT`, `PGDATABASE`, `PGUSER`, `PGPASSWORD`
у приватному оточенні запуску. Не комітьте їхні значення.

## Архітектура Onion

Backend містить чотири проєкти: Domain, Application, Infrastructure та Api.
Application містить сценарії створення/читання, валідацію та DTO; EF-адаптери реалізують його контракти зберігання.
Infrastructure/Persistence містить Configurations, Repositories і Migrations.
HTTP endpoints використовують контракти застосунку/платформи; Infrastructure підключається в Program.cs.
Див. [архітектуру та правила залежностей](docs/ARCHITECTURE.md). Випуск зберігає
першу міграцію й наявні дані; схема розширюється міграцією відповідей. Далі — 1.1.0.8 SortingPagination.

## Перевірка frontend

З Node.js 24 виконайте `npm ci`, `npm test`, `npm run build` у `src/comments-web`.
Форма надсилає звичайний текст або дозволений XHTML; обов’язкові поля позначено. Email публікується.
Таблиця показує останні 25 записів із місцевим часом. «Оновити» повторює читання.
Помилки полів сервера виводяться в початковому вигляді; інтерфейс підтримує EN/RU/UA.
За помилки надсилання чернетка залишається у формі; перед повтором невизначеного запиту
оновіть список, щоб уникнути дублів. Повне сортування/пагінація і CAPTCHA — наступні етапи.

## XHTML-редактор

Дозволено `a`, `i`, `strong`, `code`. Посилання потребує абсолютного HTTP(S) `href` без облікових даних; `title` необов’язковий. Решту атрибутів, простори імен, вкладені посилання, коментарі, DTD/CDATA, неправильну вкладеність і небезпечні адреси заборонено. XHTML потребує закритих тегів нижнього регістру та XML-сутностей (`&amp;`, `&lt;`, `&quot;`); звичайний текст `1 < 2 && 3 > 1` також дозволено. Обмеження: 65 536 одиниць UTF-16, глибина 32 та 4096 вузлів парсера.

Виділіть текст і натисніть «Жирний», «Курсив», «Код» або «Посилання». Посилання вставляє редагований HTTPS-шаблон. «Перегляд» надсилає `POST /api/comments/preview` з `{ "text": "<strong>Hello</strong>" }` та отримує `{ "html": "<strong>Hello</strong>" }` без звернення до БД чи запису. Збереження використовує той самий валідатор Application. Редагування приховує застарілий перегляд; помилка зберігає чернетку. Перегляд і таблиця створюють лише дозволені React-елементи, безпечні посилання та екранований текст у разі відмови. Наявні записи збережено; схема розширюється міграцією відповідей.

Підказка необов’язкового поля сайту вимагає повну адресу, наприклад `https://example.com`; `http://` також підтримується. Форма не обирає протокол і не перевіряє доступність сайту.

## Гілки коментарів

Відповісти можна на будь-який наявний коментар. Натисніть «Відповісти» під записом; форма покаже адресата. «Скасувати відповідь» повертає створення кореня й зберігає чернетку. Успішна відповідь з’являється під батьківським записом; відсутній адресат спричиняє помилку без створення автора чи коментаря.

Таблиця показує до 25 нових коренів. «Показати/Приховати відповіді» розгортає прямі відповіді; «Ще відповіді» завантажує наступні 25. Корені й сусіди впорядковано за часом UTC та UUID за спаданням. Глибина обговорення не обмежена застосунком: виведення ітеративне, візуальний відступ перестає зростати після шести рівнів, числовий рівень продовжує зростати. «Оновити» перечитує корені й відкриті гілки; помилка гілки пропонує «Повторити» та зберігає завантажений вміст. Повні сторінки/сортування коренів — етап 1.1.0.8.

API: POST /api/comments приймає необов’язковий parentId (UUID/null); rootId визначає сервер, передавати його не можна. GET /api/comments/{id}/replies?limit=25&after={replyId} повертає {items,nextAfter}; для першої порції after не вказується. Limit — 1–100; after має бути прямою відповіддю цьому батьківському запису. Немає батьківського запису: 404 під час читання, помилка parentId (400) під час запису. Невідомий/чужий курсор — 400. Порції обмежують сусідні відповіді, а не глибину. API видалення/редагування не додано.
