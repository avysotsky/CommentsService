У цій версії frontend React та API .NET працюють разом в одному Docker-контейнері.
Окрема PostgreSQL використовує постійне сховище. Необов’язковий окремий сервіс
PostgreSQL надає постійну БД інтеграційних тестів.

Коментарі, сутності Entity Framework і доступ застосунку до БД ще не реалізовані;
наступна ітерація — DataModel. Англомовна стартова сторінка показує з’єднання
з API та випуск. Це етап розробки, а не завершений сервіс коментарів.

## Розгортання на власній інфраструктурі

Потрібні Docker Engine, Docker Compose v2.24+, Git і Python 3 для генерування паролів.
Docker збирає .NET і React; окремі .NET/Node на сервері не потрібні.
Із кореня клонованого репозиторію:

```bash
python3 scripts/init-env.py
docker compose -p commentsservice up -d --build --wait
curl --fail http://127.0.0.1:8080/health
```

Відкрийте http://localhost:8080 на машині з Docker. Якщо установка потребує,
використовуйте sudo для Docker-команд. Перший запуск ініціалізує порожній том БД;
наступні зберігають його. `--wait` очікує перевірок готовності контейнерів.

`commentsservice` — приклад назви проєкту. Можна вибрати власну, але зберігайте її
під час оновлень, щоб використовувати попередні томи. Під час генерування оточення
можна вибрати інший вільний порт застосунку, наприклад
`python3 scripts/init-env.py --port 8081`.

## Постійні бази даних

- `database`: база `comments`, том `commentsservice_development_data`.
- `test-database`: база `comments_test`, том `commentsservice_test_data`;
  вмикається необов’язковим профілем `testing`.
- Кожен сервіс має окремий пароль і прикладну роль `comments_app` без SUPERUSER.
- Прикладних таблиць і міграцій EF у цій ітерації ще немає.

Щоб запустити також постійну тестову БД:

```bash
docker compose -p commentsservice --profile testing up -d --wait test-database
```

Тестова БД доступна лише через 127.0.0.1:55434. Інший порт задається параметром
`--test-db-port` під час генерування паролів. Порт основної БД назовні не публікується.
Тести зберігають БД, відкочують зміни або видаляють лише власні записи.
Повторне створення БД і TRUNCATE спільних таблиць не використовуються для звичайних тестів.

Зупинка контейнерів зі збереженням даних:

```bash
docker compose -p commentsservice --profile testing down
```

Не використовуйте `down -v`, якщо дані потрібно зберегти. Для оновлення виберіть
гілку потрібного випуску та повторіть запуск із попередньою назвою проєкту й файлом оточення.
Перед майбутніми змінами схеми/даних зберігайте перевірену попередню контрольну копію.

## Паролі й доступ

Ініціалізатор один раз створює приватний .env із випадковими паролями та не
перезаписує наявний файл. Не комітьте й не передавайте цей файл. Якщо наявний
файл неповний, створіть окремий через `--output` і передайте Compose параметр
`--env-file`. Зміна .env не змінює паролі наявних ролей PostgreSQL.

Порт застосунку прив’язаний до 127.0.0.1. Для зовнішнього доступу підключіть власний
HTTPS reverse proxy; ця версія не створює домен і публічний хостинг.

## Перевірка стану

`GET /api/status` повертає:

```json
{"application":"CommentsService","version":"1.1.0.2","stage":"Docker"}
```

`GET /health` перевіряє готовність процесу API. Готовність PostgreSQL перевіряється
Compose окремо; застосунок поки не підключається до баз. Контейнер застосунку
працює від непривілейованого користувача. У Dockerfile та скриптах немає вбудованих
паролів або інструкцій конкретного робочого комп’ютера.

## Відкриття у Visual Studio

Відкрийте `CommentsService.slnx` у Visual Studio 2026 з установленим робочим навантаженням ASP.NET і веброзробки та SDK .NET 10. Рішення містить проєкт API й папку рішення Frontend із вихідними файлами React та файлами збирання. Frontend залишається застосунком npm/Vite; збирання рішення збирає лише API. Для збирання та запуску всього застосунку використовуйте Docker-інструкцію вище.
