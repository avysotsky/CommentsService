# CloudAttachments 1.3.3.4

## EN

Supabase Storage Free is an optional mirror for explicitly approved image/TXT attachments. PostgreSQL retains every original and remains authoritative; comment/file writes never wait for Cloud. Existing REST/GraphQL, CAPTCHA, preview, search, Events, RabbitMQ, cache and WS remain available when Cloud is absent or restricted. Only explicitly listed own test comments may be mirrored in this release. No SQL migration, backfill, outbox or replica deployment.

Application owns CloudAttachment/IAttachmentCloud/ICloudAttachmentSource/ICloudCopySignals. Infrastructure owns canonical EF reads, consent-gated post-commit signals and the bounded Supabase HTTP adapter. API composes them and runs the worker; Domain has no provider dependencies. Existing attachment routes and safe headers remain. The browser receives no Supabase URL, key or signed links.

Write: validate/normalize using the original pipeline, commit comment and attachment atomically to SQL, then enqueue an approved comment ID via Events. A bounded in-memory lane is needed because the existing WS queue coalesces change notifications. No new Rabbit queue/consumer or broker dependency is added. Worker reloads SQL and copies canonical PNG or exact UTF-8 TXT. Object keys use schema version, database-name SHA256 partition, type, UUID and full content hash; user filenames are never paths. Uploads use deterministic upsert, so finite retries do not create duplicate paths.

Read: fetch SQL first and require an approved CommentId; attempt the private object through backend, verify complete length and SHA256 before returning any provider bytes; otherwise return the SQL bytes. Unknown/deleted SQL IDs stay 404. Proxying preserves one-request fallback and original headers/CSP. It keeps home-server traffic and SQL blob reads, consumes provider egress, and makes no speed or cached-CDN quota claim. This is an additional copy, not a database-size reduction or backup replacement.

Defaults: Cloud disabled, AllowedCommentIds and ReplayCommentIds empty. Enable Runtime.Cloud only after owner approval. AllowedCommentIds is a maximum-64 explicit consent list; ReplayCommentIds must be its subset and is processed once per process start. No bucket/SQL scan, automatic history migration or implicit authorization for new user uploads exists. To retry, deliberately configure the exact approved IDs for replay; remove them when finished. No public replay endpoint exists.

Policies in backend config.json: Capacity64, MaximumConcurrency2, MaximumAttempts3, WriteTimeoutSeconds5, ReadTimeoutMilliseconds1000, RetryDelayMilliseconds500 (linear backoff plus jitter), FailureThreshold5, BreakSeconds300, MaximumUploadBytes10485760, MaximumDownloadBytes20971520, MaximumRequests256. These are hard upper bounds on configurable settings. Each write attempt has a total deadline including slot wait and metadata validation. Reads use no queue wait and one total deadline, then SQL; no read retry. Worker is sequential; foreground reads and writes share two HTTP slots. Full signals are dropped without delaying a committed comment. 5xx/network failures have finite attempts/circuit backoff; 429 suspends work with bounded Retry-After for writes; 400/401/402/403 stop Cloud until operator correction/restart. Other non-success responses fall back; redirects are disabled. Provider errors/bodies/keys are not logged.

Byte/request reservations include attempts and bounded metadata/ack responses; limits apply per process, not as persistent monthly accounting. Restart resets counters, circuit state and pending jobs; explicit replay may consume traffic again. No durable delivery, outbox or automatic guaranteed catch-up is provided. Check organization Usage/Billing and notifications; these local limits do not represent all projects' usage or a total bucket-size quota. Keep regular user uploads disabled.

Setup: use a dedicated Free organization/project, without a card, upgrade or paid add-ons. Supabase provisions its own service database; the application database stays on its original host. Create private bucket comments-attachments, allowed MIME image/png and text/plain, file limit5MiB. Keep public/anonymous policies absent. The adapter validates bucket privacy/MIME/size before object operations, caching successful metadata for up to5minutes. Do not change bucket visibility. A wrong/missing bucket policy fails closed to SQL.

Create a dedicated sb_secret_ backend key in project Settings/API Keys. It is a broad project credential bypassing RLS, not a bucket-scoped key; isolate the project. Set SUPABASE_URL, SUPABASE_SECRET_KEY and SUPABASE_BUCKET only in a private runtime environment file. Compose optionally reads .env.cloud; existing deployments can use their private override/env_file. Do not put values in config.json, CLI arguments, browser code, source control, build arguments, image layers or logs. .env.cloud/.local are ignored by Git and Docker. No Management API/account token or SQL password is needed by the app. The adapter only accepts HTTPS *.supabase.co endpoints and new secret keys; HTTPS redirects are not followed.

Free terms checked2026-11-01:1GB files,5GB uncached plus separate5GB cached egress per cycle, max50MB/file, two active free projects, pause after a week of inactivity. Quotas aggregate at organization level. Free has no usage charge, but over-quota service restriction/402 or pause is possible after notification/grace; abuse can be restricted immediately. No guaranteed warning period or availability. Owner resumes a paused project; no artificial keepalive or automatic paid upgrade. Basic CDN does not guarantee use of the entire cached allowance.

Upgrade1.3.3.3->1.3.3.4: rebuild/recreate only the app with the same project, private environment, all deployment Compose overrides and original persistent volumes. No SQL schema/data migration or new service/volume. Keep verified checkpoints and all earlier data. Rollback: disable Cloud/remove consent lists, or restore the previous app image with the same deployment files; SQL originals remain readable. Cleanup is limited to exact recorded owned test objects and fixture IDs, never a bucket purge. Cloud objects can outlive SQL rows; SQL existence prevents serving them, and this release does not implement global orphan collection.

## RU

Supabase Storage Free — дополнительная копия явно разрешённых изображений/TXT. Все оригиналы остаются в PostgreSQL; запись комментария и файла не ждёт Cloud. REST/GraphQL, CAPTCHA, preview, поиск, Events, RabbitMQ, кеш и WS сохраняются при отсутствии или ограничении облака. В этом выпуске разрешены только собственные тестовые комментарии из явного списка. Миграции SQL, массового переноса, outbox и реплик нет.

Application владеет CloudAttachment/IAttachmentCloud/ICloudAttachmentSource/ICloudCopySignals. Infrastructure содержит SQL-чтение, сигналы после commit с проверкой разрешения и ограниченный HTTP-адаптер Supabase. API собирает зависимости и запускает worker; Domain не зависит от провайдера. Старые маршруты файлов и защитные заголовки сохранены. Браузер не получает URL Supabase, ключи или подписанные ссылки.

Запись: прежняя проверка/нормализация, единая транзакция SQL, затем Events передаёт только разрешённый ID комментария. Отдельный ограниченный буфер в памяти нужен, потому что прежняя WS-очередь объединяет уведомления об изменениях. Новых очередей/consumer Rabbit и зависимости от брокера нет. Worker перечитывает SQL и копирует нормализованный PNG или точный UTF-8 TXT. Ключ объекта содержит версию, SHA256-раздел имени БД, тип, UUID и полный хеш содержимого; имя пользователя не используется как путь. Детерминированный upsert не создаёт новых путей при повторах.

Чтение: сначала SQL и проверка разрешённого CommentId, затем приватный объект через backend. Длина и SHA256 проверяются до выдачи облачных байтов; при ошибке возвращается SQL-копия. Неизвестные/удалённые SQL ID дают404. Прокси сохраняет fallback в одном запросе, заголовки и CSP. Домашний трафик и чтение SQL-байтов остаются, расходуется egress провайдера; ускорение и полное использование кешированной квоты не обещаны. Это не уменьшение БД и не замена резервирования.

По умолчанию Cloud выключен, AllowedCommentIds/ReplayCommentIds пусты. Включать Runtime.Cloud только с разрешения владельца. AllowedCommentIds — явный список максимум64 комментариев; ReplayCommentIds — его подмножество, обрабатывается один раз при старте процесса. Сканирования SQL/bucket, переноса истории и разрешения будущих пользовательских загрузок нет. Для повторной отправки явно указать точные разрешённые ID и убрать после проверки. Публичного endpoint повтора нет.

Политики backend config.json: Capacity64, MaximumConcurrency2, MaximumAttempts3, WriteTimeoutSeconds5, ReadTimeoutMilliseconds1000, RetryDelayMilliseconds500 с линейной задержкой и случайным разбросом, FailureThreshold5, BreakSeconds300, MaximumUploadBytes10485760, MaximumDownloadBytes20971520, MaximumRequests256. Это верхние границы настроек. Срок попытки записи включает ожидание слота и проверку bucket. Чтение не ждёт очередь, имеет общий срок и не повторяется. Worker последовательный, чтение/запись делят два HTTP-слота. Переполнение не задерживает сохранённый комментарий. Сеть/5xx — конечные повторы и пауза;429 — ограниченный Retry-After записи;400/401/402/403 останавливают Cloud до исправления/рестарта. Прочие ошибки дают fallback, redirect запрещён. Ключи/тексты исключений/ответы провайдера не логируются.

Бюджет учитывает попытки, ограниченные ответы метаданных и подтверждений; он действует на процесс, не является постоянным месячным учётом. Рестарт сбрасывает счётчики, circuit и задания; явный replay снова расходует трафик. Долговечность/outbox/гарантированное автоматическое догоняние не заявлены. Проверять Usage/Billing и уведомления организации: локальный бюджет не охватывает чужое потребление и не является квотой всего bucket. Обычные пользовательские загрузки оставить отключёнными.

Настройка: отдельные организация/проект Free без карты, платного тарифа и дополнений. Supabase создаёт служебную БД; основная БД приложения остаётся на месте. Приватный bucket comments-attachments: image/png,text/plain, лимит5МиБ; без публичных/анонимных политик. Адаптер проверяет приватность/MIME/размер, кешируя успешную проверку до5минут. Видимость bucket не менять. Неверная политика/отсутствие bucket дают только SQL.

Создать отдельный sb_secret_ в Settings/API Keys. Это широкий ключ проекта, обходящий RLS, а не права одного bucket; проект изолировать. SUPABASE_URL/SUPABASE_SECRET_KEY/SUPABASE_BUCKET задаются только приватным runtime env-файлом. Compose необязательно читает .env.cloud; рабочая установка использует прежний приватный override/env_file. Значения запрещены в config.json, CLI, frontend, Git, build args, образе и логах. .env.cloud/.local исключены Git/Docker. Management API token и пароль SQL приложению не нужны. Разрешены только HTTPS *.supabase.co и новые secret keys, без переходов HTTPS redirect.

Условия Free проверены01.11.2026:1ГБ файлов,5ГБ обычного и отдельно5ГБ кешированного egress за цикл,50МБ/файл, два активных бесплатных проекта, пауза после недели бездействия. Квоты общие для организации. Free не списывает оплату за использование, но возможны ограничения/402/пауза после уведомления/льготного периода; злоупотребление может ограничиваться сразу. Срок предупреждения и доступность не гарантированы. Проект возобновляет владелец; искусственного keepalive/перехода на оплату нет. Basic CDN не гарантирует расход всей кешированной квоты.

Обновление1.3.3.3->1.3.3.4: пересобрать/пересоздать только app с прежними проектом/env/всеми Compose overrides/томами. Без миграции SQL/данных и новых сервисов/томов. Копии и прежние данные сохранять. Откат: выключить Cloud/убрать списки либо вернуть предыдущий образ с прежними файлами запуска; SQL-оригиналы доступны. Очистка — только точные учтённые собственные объекты/фикстуры, не весь bucket. Объект может пережить SQL-строку; проверка SQL запрещает его выдачу, глобальной очистки сирот нет.
