# Backend configuration / Конфигурация / Конфігурація

## English

Deployment adds `Runtime.Proxy.KnownProxies`: up to16 explicit IP addresses, default empty (forwarding disabled), with no wildcard/unspecified addresses. Configure only the immediate transport peer seen by the API. The API accepts one symmetric forwarded IP/scheme hop and emits HSTS for forwarded HTTPS. See [deployment](DEPLOYMENT.md).

Configuration is read once at startup. Defaults → selected JSON → environment → command line. `APP_CONFIG` selects an absolute backend JSON file; an explicit missing, malformed or invalid file stops startup with a generic error. Without it, the shipped `config.json` beside the assembly supplies defaults. Keep configuration outside `wwwroot`.

`Runtime` settings: `InstanceId` (1–64 ASCII letters/digits/hyphen/underscore), `HealthPort` (1–65535), `Database` with optional `Host`, `Database`, `Username`, `Port` (1–65535), `TimeoutSeconds`/`CommandTimeoutSeconds` (1–300), `MaximumPoolSize` (1–1000). Passwords remain in `PGPASSWORD`. Existing `PGHOST`, `PGPORT`, `PGDATABASE`, `PGUSER` override their JSON equivalents. `Runtime__InstanceId` demonstrates environment overrides; `--Runtime:InstanceId=second` demonstrates CLI overrides. The same loading applies to `--migrate`, `--check-database` and `--healthcheck`; options can follow the command. HealthPort must match the actual HTTP listener selected with ASPNETCORE_HTTP_PORTS/URLs.

For Docker, copy `compose.config.example.yaml` to an override and set `APP_CONFIG_FILE` to your private host file. Use it alongside your usual Compose files and environment, retaining the project and volumes. It mounts `/app/config/config.json` read-only. Distinct instances require distinct identities, ports and mounts; independent data also requires distinct databases/storage. The frontend uses relative `/api` and receives no private configuration. CAPTCHA remains process-local; shared-site replicas require sticky routing or a separately designed shared store. Operational CAPTCHA, page-size and upload/request limits are now configured through Runtime policies; fixed schema/security ceilings remain enforced. See [all keys, ranges and verification](RUNTIME_LIMITS.md). Restart to apply changes; there is no hot reload.

## Русский

Deployment добавляет `Runtime.Proxy.KnownProxies`: до16 явных IP, по умолчанию пусто (forwarding выключен), без wildcard/неопределённых адресов. Указывайте только непосредственный transport peer, видимый API. Принимается один симметричный hop IP/схемы, для forwarded HTTPS выдаётся HSTS. [Развёртывание](DEPLOYMENT.md).

Конфигурация читается при старте: defaults → выбранный JSON → окружение → командная строка. `APP_CONFIG` выбирает абсолютный путь backend JSON; отсутствие явно выбранного файла, повреждение или неверные значения останавливают запуск с общей ошибкой. Без него используется `config.json` рядом со сборкой. Храните конфиг вне `wwwroot`.

Секция `Runtime`: `InstanceId` (1–64 ASCII-буквы/цифры/дефис/подчёркивание), `HealthPort` (1–65535), `Database`: необязательные `Host`, `Database`, `Username`, `Port` (1–65535), `TimeoutSeconds`/`CommandTimeoutSeconds` (1–300), `MaximumPoolSize` (1–1000). Пароль — только `PGPASSWORD`. Прежние `PGHOST`, `PGPORT`, `PGDATABASE`, `PGUSER` имеют приоритет над JSON. Примеры переопределений: `Runtime__InstanceId` в окружении и `--Runtime:InstanceId=second` в CLI. Загрузка едина для `--migrate`, `--check-database`, `--healthcheck`; параметры могут следовать после команды. HealthPort должен совпадать с HTTP-портом ASPNETCORE_HTTP_PORTS/URLs.

Для Docker скопируйте `compose.config.example.yaml` в override, задайте `APP_CONFIG_FILE` своим приватным файлом и подключите вместе с обычными Compose-файлами/окружением, сохраняя проект/тома. Монтирование `/app/config/config.json` доступно только для чтения. Разным инстансам нужны разные идентификаторы, порты и файлы; независимым данным — отдельные БД/хранилища. Frontend использует относительный `/api`, приватный конфиг ему не передаётся. CAPTCHA остаётся в процессе; реплики общего сайта требуют sticky routing либо отдельно спроектированного хранилища. Рабочие параметры CAPTCHA, размера страницы, загрузок/запросов теперь настраиваются через Runtime; обязательная CAPTCHA и пределы схемы/безопасности сохранены. [Все ключи, диапазоны и проверки](RUNTIME_LIMITS.md). Для изменений нужен перезапуск, hot reload нет.

## Українська

Deployment додає `Runtime.Proxy.KnownProxies`: до16 явних IP, типово порожньо (forwarding вимкнено), без wildcard/невизначених адрес. Указуйте лише безпосередній transport peer, видимий API. Приймається один симетричний hop IP/схеми, для forwarded HTTPS видається HSTS. [Розгортання](DEPLOYMENT.md).

Конфігурація читається під час старту: defaults → вибраний JSON → оточення → командний рядок. `APP_CONFIG` обирає абсолютний шлях backend JSON; відсутність явно вибраного файла, пошкодження чи хибні значення зупиняють запуск із загальною помилкою. Без нього використовується `config.json` поряд зі збіркою. Зберігайте конфіг поза `wwwroot`.

Секція `Runtime`: `InstanceId` (1–64 ASCII-літери/цифри/дефіс/підкреслення), `HealthPort` (1–65535), `Database`: необов’язкові `Host`, `Database`, `Username`, `Port` (1–65535), `TimeoutSeconds`/`CommandTimeoutSeconds` (1–300), `MaximumPoolSize` (1–1000). Пароль — лише `PGPASSWORD`. Попередні `PGHOST`, `PGPORT`, `PGDATABASE`, `PGUSER` мають пріоритет над JSON. Приклади перевизначень: `Runtime__InstanceId` в оточенні та `--Runtime:InstanceId=second` у CLI. Завантаження єдине для `--migrate`, `--check-database`, `--healthcheck`; параметри можуть іти після команди. HealthPort має відповідати HTTP-порту ASPNETCORE_HTTP_PORTS/URLs.

Для Docker скопіюйте `compose.config.example.yaml` в override, задайте `APP_CONFIG_FILE` своїм приватним файлом і додайте разом зі звичайними Compose-файлами/оточенням, зберігаючи проєкт/томи. Монтування `/app/config/config.json` доступне лише для читання. Різним інстансам потрібні різні ідентифікатори, порти й файли; незалежним даним — окремі БД/сховища. Frontend використовує відносний `/api`, приватний конфіг йому не передається. CAPTCHA лишається в процесі; реплікам спільного сайту потрібні sticky routing чи окремо спроєктоване сховище. Робочі параметри CAPTCHA, розміру сторінки, завантажень/запитів тепер налаштовуються через Runtime; обов’язкову CAPTCHA й межі схеми/безпеки збережено. [Усі ключі, діапазони й перевірки](RUNTIME_LIMITS.md). Зміни потребують перезапуску, hot reload немає.
