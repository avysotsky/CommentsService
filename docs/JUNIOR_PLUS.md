# Junior+ — 1.2.2.4 LiveComments

## English — current behavior

All four Junior+ tools are integrated: commit comment/attachment in PostgreSQL → publish `CommentCreated` → synchronously invalidate the read cache and enqueue a refresh hint → hosted worker → bounded WebSocket fan-out → browser update notice → existing REST queries. Domain remains independent; Application owns event/delivery ports and its DTOs; Infrastructure owns EF/cache/channel adapters; API owns HTTP, hosting and WebSocket connections. No Middle/Middle+ technology, schema change, new database or durable broker is introduced.

`GET /api/comments/live` upgrades to WebSocket only for an exact same-origin browser request. Missing/foreign Origin is rejected (403), plain HTTP is 400, disabled realtime is 404 and exhausted connection capacity is 503. Each connection has one coalescing pending hint, one sender and one receiver. Slow sends time out and release the connection slot; idle connections exchange native ping/pong. Shutdown cancels connections. Incoming application data is unsupported and ends the connection; the endpoint cannot create comments or run queries. Frames contain only `{"type":"connected"}` or `{"type":"commentsChanged"}`, never comment content or client metadata. There is no message history, acknowledgement or exactly-once guarantee.

The SPA displays a localized update notice without moving a reader's page/sort or replacing a draft. Refresh reloads the current root page and expanded reply branches. On connection/reconnection, it re-reads the current view to recover missed hints. Reconnect uses bounded exponential delay, reset after the server's connected frame; offline/manual refresh remains usable. Browser cleanup cancels reconnect timers and closes the socket. Changes arriving during an HTTP fetch retain the notice. This release is a single-process deployment: cache/queue/subscriptions are process-local; external SQL writes expire from cache by TTL and require manual refresh, and multi-replica coherence is not claimed.

## Notification queue / Очередь уведомлений / Черга сповіщень — 1.2.2.3

EN: A committed event invalidates the cache synchronously and enqueues a content-free refresh hint in a bounded `System.Threading.Channels` channel. The request never waits for a client connection. DropOldest coalesces overload: every remaining hint means refresh the whole current view, so a newer hint covers earlier changes. A single hosted worker delivers hints through the Application `ICommentChangeDelivery` port. Delivery is idempotent; failures retry at a fixed delay up to the configured maximum, log metadata-only warnings and then move to the next hint. Shutdown cancels retries/reads and completes the writer. Pending hints can be lost on crash/shutdown; comments cannot be lost by this queue. Reconnect/manual refresh is the recovery mechanism. Coalesced hint counts are logged when the worker stops. This iteration's consumer logs delivery at Debug; WebSocket fan-out is wired in the next iteration. This is not a durable job queue or external broker.

RU: Событие записи синхронно сбрасывает кеш и добавляет сигнал без содержимого в ограниченный канал `System.Threading.Channels`. Запрос не ждёт соединения клиента. DropOldest объединяет перегрузку: каждый оставшийся сигнал обновляет всё текущее представление и покрывает прежние изменения. Один фоновый обработчик доставляет сигналы через порт Application `ICommentChangeDelivery`. Доставка идемпотентна; ошибки повторяются с фиксированной задержкой до заданного числа попыток, пишут предупреждение без содержимого и переходят к следующему сигналу. Остановка отменяет повторы/чтение и закрывает запись канала. При аварии/остановке сигналы могут потеряться; комментарии от этой очереди не зависят. Восстановление — переподключение/ручное обновление. При остановке журналируется число объединений. Потребитель этой итерации пишет доставку на уровне Debug; WebSocket подключается в следующей. Это не долговечная очередь заданий и не внешний брокер.

## Read cache / Кеш чтения / Кеш читання — 1.2.2.2

EN: `CachedCommentQueries` decorates the Application read port in Infrastructure. Only root pages and latest-root lists are cached; keys include page, size, sort and direction (or latest limit). Replies, individual comments, attachments, CAPTCHA and validation are never cached. Results have read-only item collections. The singleton retains values, never scoped DbContexts. Explicit caller transactions bypass caching. Every committed comment event clears the entire cache synchronously; a generation check rejects any in-flight fill started before invalidation. Expired values are replaced on demand; FIFO eviction bounds both entry count and estimated retained bytes (UTF-16 text plus metadata allowance). This is a memory budget estimate, not a measurement of the complete process heap. Concurrent misses can query independently. Failed/cancelled reads never fill the cache. External SQL changes and other app instances become visible within TTL; this release targets one app instance. Health checks always query the database independently.

RU: `CachedCommentQueries` декорирует порт чтения Application в Infrastructure. Кешируются только страницы корней и списки последних корней; ключи включают страницу, размер, сортировку и направление либо лимит последних записей. Ответы, отдельные комментарии, вложения, CAPTCHA и валидация не кешируются. Коллекции результатов доступны только для чтения. Singleton хранит значения, не scoped DbContext. Явная транзакция вызывающего обходит кеш. Каждое событие сохранённого комментария синхронно сбрасывает весь кеш; проверка поколения запрещает заполнение запросом, начатым до сброса. Истёкшие значения заменяются при чтении; FIFO ограничивает количество и оценку байтов (UTF-16 и запас на метаданные). Это оценка памяти кеша, не замер всей памяти процесса. Одновременные промахи могут независимо обращаться к БД. Ошибки/отмена не заполняют кеш. Внешние SQL-изменения и другие инстансы видны не позднее TTL; выпуск рассчитан на один инстанс. ## English

The original assignment requires Queue, Cache, Events and WebSocket for Junior+. These are being delivered incrementally; this release implements Events only. `CreateComment` publishes an immutable `CommentCreated` fact after successful `SaveChanges`. It carries event/comment/parent/root identifiers and the comment creation time, without text, e-mail, IP, User-Agent or attachments. The Application owns event contracts; Infrastructure dispatches subscribers through DI. The initial subscriber writes a structured `Comment committed` log. Each subscriber is isolated: failure produces a metadata-only warning, remaining subscribers run, and the committed HTTP result stays successful. Cancellation during persistence produces no event; request cancellation after commit does not suppress dispatch. This is a process-local post-commit mechanism, not a durable audit trail or transactional outbox. A process crash between commit and dispatch can lose a notification; stored comments remain authoritative.

Configuration, JSON/REST, database schema and portable installation commands are unchanged. Upgrade by rebuilding the app with your existing Compose project, overrides, environment and volumes. No migration or data regeneration is required. Cache, queue and WebSocket are subsequent iterations, not completed features of this release. Tests cover invalid input, failed persistence, root/reply identity, event ordering and subscriber failure isolation.

Отмена во время сохранения не создаёт события; отмена запроса после сохранения не подавляет отправку. Это локальное событие процесса, не долговечный аудит или transactional outbox. При аварии между сохранением и отправкой уведомление может потеряться; источником данных остаётся БД.

Конфиг, JSON/REST, схема и переносимые команды установки прежние. Для обновления пересоберите приложение с прежними Compose-проектом, overrides, окружением и томами. Миграции и генерация данных не нужны. Кеш, очередь и WebSocket — следующие итерации, а не готовые функции этого выпуска. Тесты проверяют неверный ввод, ошибку сохранения, идентификаторы корня/ответа, порядок события и изоляцию ошибок подписчиков.

## Українська

Junior+ вимагає Queue, Cache, Events і WebSocket. Постачання відбувається невеликими ітераціями; цей випуск реалізує лише Events. `CreateComment` публікує незмінний факт `CommentCreated` після успішного `SaveChanges`: ідентифікатори події/коментаря/батька/кореня та час коментаря, без тексту, e-mail, IP, User-Agent і вкладень. Контракти належать Application, диспетчеризація через DI — Infrastructure. Перший підписник пише структурований лог `Comment committed`. Збій кожного підписника ізольовано: попередження містить лише службові дані, інші підписники виконуються, успішний запис залишається успішним. Скасування під час збереження не створює події; скасування запиту після збереження не пригнічує надсилання. Це локальна подія процесу, не довговічний аудит або transactional outbox. У разі аварії між збереженням і надсиланням сповіщення може втратитись; джерелом даних залишається БД.

Конфіг, JSON/REST, схема й переносимі команди встановлення попередні. Для оновлення перебудуйте застосунок із попередніми Compose-проєктом, overrides, оточенням і томами. Міграції та генерація даних не потрібні. Кеш, черга та WebSocket — наступні ітерації, а не готові функції цього випуску. Тести перевіряють хибне введення, помилку збереження, ідентифікатори кореня/відповіді, порядок події й ізоляцію помилок підписників.
