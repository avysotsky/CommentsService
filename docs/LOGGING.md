# Structured logging / Структурированные логи / Структуровані логи

## English

One DI-managed Serilog pipeline writes JSON lines to console and file. `Runtime.Logging` in config.json controls `MinimumLevel` (Verbose/Debug/Information/Warning/Error/Fatal), category `Overrides`, `Directory`, `FileSizeLimitBytes` (1024–1073741824) and `RetainedFileCountLimit` (1–365). Files use InstanceId, daily and size rolling. Restart to apply settings. Defaults: Information, logs, 10 MiB, 14 retained files. Docker uses the dedicated `application_logs` volume; retain it across recreation and mount separate log storage for independent instances.

Events include timestamp, severity, category, InstanceId and request TraceId; HTTP completion includes method, route template, status and elapsed milliseconds. Startup/shutdown and database CLI outcomes are recorded. Only CommentsService categories enter this pipeline, preventing raw framework/provider diagnostics from bypassing the public-data policy. Exceptions record type/status, not messages/bodies. Passwords, connection strings, CAPTCHA content, comment/file bodies, e-mail, IP and query values are excluded. Inner layers keep their framework independence; logging remains at the host boundary. A write probe checks the directory at startup; later sink failures produce a generic stderr diagnostic. Host disposal flushes the sinks. File-system failure can still lose events; stderr must be monitored.

## Русский

Единая управляемая DI система Serilog пишет JSON-строки в консоль и файл. `Runtime.Logging` в config.json задаёт `MinimumLevel` (Verbose/Debug/Information/Warning/Error/Fatal), категории `Overrides`, `Directory`, `FileSizeLimitBytes` (1024–1073741824), `RetainedFileCountLimit` (1–365). Имя содержит InstanceId, ротация — по дате и размеру. Для изменений нужен перезапуск. По умолчанию Information, logs, 10 МиБ, 14 файлов. Docker использует отдельный том `application_logs`; сохраняйте его при пересоздании и выделяйте отдельное хранилище независимым инстансам.

События содержат время, уровень, категорию, InstanceId и TraceId запроса; завершение HTTP — метод, шаблон маршрута, статус и длительность. Записываются старт/остановка и результаты CLI БД. В систему проходят только категории CommentsService: сырая диагностика фреймворка/провайдера исключена. Для исключения пишутся тип/статус, без сообщения/тела. Пароли, строки подключения, CAPTCHA, тексты комментариев/файлов, e-mail, IP и значения query исключены. Внутренние слои независимы от фреймворков, логи остаются на границе host. При старте проверяется запись в каталог, последующие сбои дают общую диагностику stderr. Освобождение host сбрасывает файлы. При сбое файловой системы возможна потеря событий; stderr нужно отслеживать.

## Українська

Єдина керована DI система Serilog пише JSON-рядки в консоль і файл. `Runtime.Logging` у config.json задає `MinimumLevel` (Verbose/Debug/Information/Warning/Error/Fatal), категорії `Overrides`, `Directory`, `FileSizeLimitBytes` (1024–1073741824), `RetainedFileCountLimit` (1–365). Назва містить InstanceId, ротація — за датою й розміром. Зміни потребують перезапуску. Типово Information, logs, 10 МіБ, 14 файлів. Docker використовує окремий том `application_logs`; зберігайте його під час перестворення й виділяйте окреме сховище незалежним інстансам.

Події містять час, рівень, категорію, InstanceId і TraceId запиту; завершення HTTP — метод, шаблон маршруту, статус і тривалість. Записуються старт/зупинка та результати CLI БД. Проходять лише категорії CommentsService: сиру діагностику фреймворку/провайдера виключено. Для винятку пишуться тип/статус, без повідомлення/тіла. Паролі, рядки підключення, CAPTCHA, тексти коментарів/файлів, e-mail, IP та значення query виключено. Внутрішні шари незалежні від фреймворків, логи лишаються на межі host. Під час старту перевіряється запис у каталог, наступні збої дають загальну діагностику stderr. Звільнення host скидає файли. Збій файлової системи може втратити події; stderr потрібно відстежувати.
